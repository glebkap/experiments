# Product Requirements Document (PRD)
## Система анализа намерений пользователей службы поддержки

**Версия:** 1.0
**Дата:** 21.11.2025
**Статус:** Draft

---

## 1. Обзор продукта

### 1.1 Назначение
Система предназначена для анализа обращений клиентов в службу поддержки с целью выявления и группировки намерений пользователей для определения реальных потребностей клиентов.

### 1.2 Цели
- Автоматизация обработки и анализа сообщений из различных источников (OKDesk, Telegram)
- Выявление паттернов и намерений пользователей на основе их обращений
- Предоставление структурированной информации для принятия бизнес-решений
- Централизованное хранение и управление данными обращений

### 1.3 Источники данных
- **OKDesk** - система учета обращений, содержащая детали заявок, комментарии и теги службы поддержки
- **Telegram** - мессенджер с историей переписки с клиентами

---

## 2. Функциональные требования

### 2.1 Парсинг и импорт данных

#### 2.1.1 Парсинг OKDesk
- Поддержка формата JSONL с полной структурой обращений
- Извлечение следующих данных:
  - Детали обращения (ID, заголовок, описание, статус, приоритет)
  - Временные метки (создание, завершение, реакция)
  - Участники (автор, исполнитель, наблюдатели)
  - Комментарии с метаданными (автор, время, публичность)
  - Теги и кастомные параметры
  - Вложения
- Обработка HTML-разметки в текстовых полях
- Поддержка nullable полей

#### 2.1.2 Парсинг Telegram
- Поддержка экспортов Telegram в формате JSON
- Извлечение сообщений с временными метками
- Идентификация участников диалога
- Обработка медиа-вложений (опционально)

#### 2.1.3 Дедупликация
- Проверка уникальности сообщений по ID источника
- Предотвращение повторной загрузки уже обработанных данных
- Обновление существующих записей при повторной загрузке

### 2.2 Обработка и анализ сообщений

#### 2.2.1 Выявление намерений
- Автоматический анализ текста сообщений с использованием NLP/LLM
- Классификация намерений по категориям:
  - Запрос информации
  - Сообщение о проблеме/инциденте
  - Запрос на изменение/доработку
  - Жалоба
  - Благодарность/отзыв
  - Консультация
- Определение уровня приоритета/срочности

#### 2.2.2 Тегирование
- Автоматическое назначение тегов на основе содержания
- Использование существующих тегов из OKDesk
- Создание новых тегов для кластеризации
- Поддержка множественных тегов для одного сообщения

#### 2.2.3 Группировка
- Кластеризация сообщений по схожим намерениям
- Выявление трендов и паттернов
- Связывание связанных обращений

### 2.3 Хранение данных

#### 2.3.1 База данных PostgreSQL
- Хранение оригинальных сообщений
- Хранение результатов анализа (намерения, теги)
- Метаданные источников и времени обработки
- Связи между сообщениями и обращениями
- История изменений

### 2.4 Интерфейсы взаимодействия

#### 2.4.1 CLI (Command Line Interface)
Текстовые команды для управления системой:

**Управление данными:**
- `import okdesk <file>` - импорт файла из OKDesk
- `import telegram <file>` - импорт файла из Telegram
- `import status` - показать статус текущего импорта
- `import history` - история импортов

**Анализ и обработка:**
- `analyze all` - запустить анализ всех необработанных сообщений
- `analyze recent [N]` - анализ последних N сообщений
- `analyze issue <id>` - анализ конкретного обращения
- `reanalyze <id>` - повторный анализ сообщения

**Просмотр и поиск:**
- `list issues [--limit N] [--status STATUS]` - список обращений с фильтрами
- `show issue <id>` - детальная информация об обращении
- `search <query>` - полнотекстовый поиск
- `search intent <intent>` - поиск по намерению
- `search tag <tag>` - поиск по тегу

**Статистика и отчеты:**
- `stats intents` - статистика по намерениям
- `stats tags` - статистика по тегам
- `stats sources` - статистика по источникам
- `stats timeline [--from DATE] [--to DATE]` - временная статистика
- `report clusters` - отчет по кластерам намерений

**Экспорт:**
- `export csv <query>` - экспорт результатов в CSV
- `export json <query>` - экспорт в JSON
- `export report <type>` - генерация отчета

#### 2.4.2 GUI (Graphical User Interface)
Веб-интерфейс, дублирующий функционал CLI:

**Главная страница:**
- Dashboard с общей статистикой
- Графики распределения намерений
- Последние импорты и анализы

**Управление импортом:**
- Загрузка файлов через drag-n-drop
- Прогресс импорта в реальном времени
- История импортов с фильтрами

**Просмотр обращений:**
- Таблица с фильтрами и сортировкой
- Детальный просмотр обращения
- Просмотр связанных сообщений

**Аналитика:**
- Интерактивные графики намерений
- Облако тегов
- Временные графики
- Группировка по кластерам

**Поиск:**
- Полнотекстовый поиск
- Фильтры по намерениям, тегам, датам, источникам
- Сохраненные запросы

**Экспорт и отчеты:**
- Выбор формата экспорта
- Настройка параметров отчета
- Скачивание результатов

## 3. Нефункциональные требования

### 3.1 Производительность
- Импорт: обработка до 10000 обращений за раз
- Анализ: обработка одного сообщения не более 5 секунд
- GUI: отклик интерфейса не более 2 секунд

### 3.2 Надежность
- Автоматический retry при сбоях
- Логирование всех операций
- Откат транзакций при ошибках

### 3.3 Безопасность
- Изоляция сервисов через Docker
- Ограничение доступа к БД
- Валидация входных данных

### 3.4 Совместимость
- Поддержка актуальных версий форматов OKDesk и Telegram
- Обратная совместимость при изменении структуры данных

---

## 4. Технические ограничения

### 4.1 Платформа
- Docker для всех сервисов
- PostgreSQL 13+ для БД
- Python 3.9+ для обработки

### 4.2 Форматы данных
- OKDesk: JSONL (JSON Lines)
- Telegram: JSON (экспорт)
- Экспорт: CSV, JSON

---

## 5. Критерии успеха

- Корректный импорт 100% файлов без дублирования
- Точность определения намерений >80%
- Покрытие тегами >90% сообщений
- Доступность системы >99%
- Время обработки одного файла <5 минут
